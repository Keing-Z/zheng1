## ③ 个人介绍（限 1000 字）

```
我是福建农林大学数据科学与大数据技术专业的本科生，目前大二在读，专业排名前 20%。

我的技术方向集中在数据处理与工程实现这条线上：从数据采集、清洗，到建模分析，再到能交付给用户的产品界面。我独立完成过四个完整项目，每一个都从需求出发，而不是从技术栈出发。

第一个是蘑菇毒性分类的机器学习项目。我在 UCI 的 8124 条样本、22 个分类特征上，用统一的预处理流程横向对比了六种模型（逻辑回归、随机森林、梯度提升、SVM、KNN、决策树），并用 5 折交叉验证评估稳定性。这个项目真正让我学到东西的地方不是“准确率多高”——恰恰相反，几乎所有树模型都达到了 100%，因为数据集的 odor 特征本身互信息就是 1.0，任务太容易了。所以我把它当成一次方法论练习：用随机森林重要性、卡方检验、互信息三种独立方法交叉验证特征贡献，得到一致的结论，并把这个“为什么全都满分”的解释写清楚，而不是直接把 100% 当作成绩。

第二个是一个微信小程序记账工具。我给自己定的唯一约束是“记一笔不超过 3 秒”，所有设计都围绕它：自绘数字键盘替代系统输入法、保存后自动清空、备注设为可选。技术上有几个我觉得值得强调的细节：金额用整数分存储规避浮点误差，日期用本地时区构造规避 UTC 偏移，环形图用 CSS 而不是 canvas。这个项目我写了 82 项自动化断言，覆盖单元、集成和静态一致性三层，过程中发现并修复了三个真实缺陷——CSV 导出丢列、文本提取顺序反转、备份恢复导致数据翻倍。

第三个是一个零依赖的 Python 网页采集工具。我特意不用 requests 和 BeautifulSoup，因为客户环境里 pip install 经常装不上，用标准库能做到“复制即运行”。为此我自己实现了轻量 DOM 树和 CSS 选择器子集。

第四个是一个 Chrome 扩展，把采集逻辑和浏览器 API 分层解耦，让核心逻辑能在 Node 里直接单元测试。

我最看重的是“能解释为什么”。一个技术选择如果说不清它放弃了什么，那就只是猜测。所以我的每个项目 README 都会写清楚：选了什么、放弃了什么、以及下一步会改什么。

我的英语可以流畅阅读技术文档并撰写英文说明。如果有编程与数据方向的任务，我希望能参与。
```

> 字数约 850，在 1000 字内。

## 一个策略建议

**先别急着提交。** 按这个顺序：

1. 先把仓库传到 GitHub（教程见 `上传GitHub教程.md`）
2. **自己在浏览器里点开链接**，确认能看到内容
3. 把简历里的占位符替换掉
4. 再回来填这四个框

因为资质申请**大概率没有第二次机会**（被拒后可能要等），第一次就交齐是最省事的。
